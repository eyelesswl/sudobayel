# ОЮН — командная игра на скорость нажатия

Создайте комнату, отправьте друзьям 6-значный код, разделитесь на 4 команды (красная, синяя, зелёная, жёлтая) и узнайте, кто нажал первым. Интерфейс на русском и кыргызском, стиль — кыргызские орнаменты.

**Стек:** Next.js 14 (App Router) · TypeScript · Tailwind CSS · Supabase (Postgres + Realtime).

## Запуск

1. **Supabase.** Создайте проект на [supabase.com](https://supabase.com) → *SQL Editor* → вставьте и выполните по очереди файлы `supabase/migrations/20261109000000_init.sql` и `20261110000000_questions.sql`.
2. **Ключи.** Скопируйте `.env.example` в `.env.local` и заполните (Supabase → *Project Settings → API*):
   - `NEXT_PUBLIC_SUPABASE_URL` — Project URL;
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` — ключ `anon` / `publishable`;
   - `SUPABASE_SERVICE_ROLE_KEY` — ключ `service_role` / `secret` (только сервер, никому не показывать).
3. **Запуск:**
   ```bash
   npm install
   npm run dev        # http://localhost:3000
   ```
   Проверка и сборка: `npm run typecheck`, `npm run build`, `npm start`.

## Как играть

0. По желанию администратор добавляет вопросы (панель администратора → «Вопросы»). Каждый «Новый раунд» показывает всем следующий вопрос по порядку; ответ видит только админ. Первый нажавший отвечает вслух, админ нажимает «Засчитать очко» — команда получает ★. Колокольчик звучит у всех, когда появляется победитель (🔔 — выключить звук). Играть можно хоть двумя командами: пустые команды просто не участвуют.
1. «Создать комнату» → введите имя → вы администратор. Скопируйте код или ссылку.
2. Остальные: «Присоединиться к комнате» → код + имя (или откройте ссылку).
3. Каждый выбирает команду — после этого кнопка активна.
4. Администратор нажимает «Новый раунд». Первый нажавший — единственный победитель на всю комнату; остальные заблокированы до следующего раунда.
5. Администратор: сброс результата, переименование команд, удаление участников (×), закрытие комнаты.

## Как это устроено

- **Победитель определяется в БД.** Функция `press_button` делает один `UPDATE rooms ... WHERE status='active' AND winner_player_id IS NULL`. При одновременных нажатиях Postgres блокирует строку, и второй запрос не находит подходящей строки — победитель всегда один.
- **Права проверяются на сервере.** Вся запись идёт через API-роуты (`src/app/api`) с ключом `service_role`. При входе игрок получает случайный токен (в БД только SHA-256), токен хранится в `localStorage` и отправляется в заголовке. Роль администратора берётся из БД, а не из запроса.
- **Браузер ничего не пишет в БД.** Для анонимного ключа закрыты все таблицы (RLS + `revoke`); доступна только чтение `room_pulse` — сигнала «комната изменилась». Получив сигнал по Realtime, клиент перечитывает состояние через API. Если Realtime недоступен, работает опрос каждые 3 секунды.
- **Локализация** — `src/lib/i18n.tsx` (RU/KG, выбор сохраняется в `localStorage`, начальный язык — русский). Названия команд по умолчанию тоже переводятся; названия, заданные админом, не переводятся.
- **Дизайн** — «Кочкор мүйүз» (логотип и фон), полоса-шырдак на карточках, шрифты Noto (поддерживают ө, ү, ң). Подпись «Субанбеков Байел» — в правом нижнем углу главной страницы на всех языках.

## Ограничения

- Нет ограничения частоты запросов (rate limit) — для публичного запуска добавьте его на уровне хостинга.
- Старые комнаты можно чистить функцией `select public.cleanup_old_rooms();` (по умолчанию удаляет комнаты старше 24 часов; её можно повесить на `pg_cron`).
- Вход без аккаунтов: потеря `localStorage` = потеря места в комнате (нужно зайти заново под другим именем).
